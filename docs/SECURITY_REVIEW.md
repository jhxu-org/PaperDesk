- 核验 vendored JavaScript／字体与 npm 对应发布包内容及完整性摘要，并按具体包版本查询 OSV 公开漏洞库。

## 修复内容

| 问题 | 修复 | 验证 |
| --- | --- | --- |
| 模型默认会话可跟随跨源跳转，307/308 可能携带论文与对话请求体 | 改为无缓存、无 Cookie 的临时会话；只允许同源跳转，同源路径跳转保持认证 | 两个真实回环 HTTP 服务分别记录请求，覆盖普通与流式调用；确认其他来源未收到请求、同源内容及认证保留、Cookie 未复用 |
| Chrome 右键导入把下载 URL 和标题放入扩展标签页地址，可能使签名参数进入历史记录 | URL 与标题改存 `chrome.storage.session`，页面只带随机 ID；一次消费、五分钟有效期、最多保留二十个待交接条目 | 自动化覆盖实际菜单事件、URL 不含原链接或标题、一次消费、过期与条目数量限制 |
| 百度 OAuth 换取／刷新令牌把 App Secret 和刷新令牌放入 URL | 改为 HTTPS POST 表单 | 协议测试断言 URL 无凭据参数、HTTP 方法／Content-Type 正确、特殊字符和刷新流程正常 |
| 原有 Git 忽略规则不足以防止误提交本机资料 | 扩展忽略规则，增加读取 Git 索引的发布内容检查 | 发布清单、个人路径检查与 Gitleaks 扫描 |

百度的 OAuth token endpoint 支持表单 POST，可参阅其[官方文档中的 POST 表单示例](https://bce-cdn.bj.bcebos.com/p3m/pdf/ai-cloud-share/online/SPEECH/SPEECH.pdf?timeStamp=1776556800091)。网盘文件接口仍按协议使用令牌查询参数，未擅自变更其认证格式。

## 已知边界

此次检查结合静态审查、自动化测试、发布文件清单检查与已知模式扫描；不是独立渗透测试或第三方安全认证，无法证明没有未知问题。

- 百度授权与上传协议使用模拟响应验证，没有使用真实用户的 AppKey、SecretKey 或网盘进行本次联调。
- 没有调用真实收费模型，也没有在全部供应商、网络代理或 Chrome 版本下验证。
- 本地文件、云端快照没有额外端到端加密；第三方模型的数据政策不受本项目控制。
- 需要系统 PDFKit/WebKit 正常处理不可信文档；没有对解析引擎进行模糊测试。
- 系统授权、浮窗等原生 UI 与 Intel 实机不属于本次新增自动化网络安全检查范围。
- OSV 的无匹配结果仅表示查询时没有该版本的匹配公开记录，不能排除未知漏洞或数据库遗漏。
